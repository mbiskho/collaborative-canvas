Collaborative Canvas: system flow

The CRDT lives in the browser. The Go relay never decodes Yjs: it stores and forwards opaque updates, so merging is the client's job and fan-out stays a pipe.

1 · Browser (React + Yjs) local edit paints in the same frame, before any network

Pointer / keyboard

drag, create, type; cursor sampled at 30 Hz into awareness

→

Y.Doc

shapes: Y.Map per shape, one key per property (LWW per field), Y.Text for text, fractional z

→

React render

observeDeep → one re-read per animation frame, not per update

→

y-indexeddb

every update persisted locally; offline edits survive a reload

→

CanvasProvider

binary frames over one WebSocket; backoff with full jitter 250 ms → 10 s

0x01 Update · Yjs update · stored + fanned out · canvas:{room}:doc
0x02 Awareness · cursor, selection, colour · fanned out only · canvas:{room}:aw
0x03 Synced · server → client · room history fully streamed
2 · Relay (Go, Gin, gorilla/websocket) any instance can serve any room: no sticky sessions

WebSocket handler

room id check, 2 MiB read limit, ping 20 s / pong 45 s, awareness limiter 30/s

→

Hub.Receive

parse type byte; reject server-only frames; fan-out before persistence

→

Local fan-out

non-blocking send into each peer's 256-frame buffer; full buffer → evict, client resyncs

→

Redis Pub/Sub

envelope = instance id + sender + frame; publisher skips its own echo

→

Other instances

deliver to their local clients in the same room

3 · Persistence Update frames only

Batch queue

256 updates or 20 ms; Load reads pending first so joins never miss one

→

COPY doc_updates

Postgres or Supabase, append-only

→

Compactor

Node + Yjs folds the log into doc_snapshots, GC'ing deleted content

4 · Drop and recovery tested by tools/chaos.ts

Socket drops

edits continue into Y.Doc + IndexedDB; peers' cursors cleared

→

Rejoin

server streams snapshot + tail + pending, then Synced

→

Full-state resend

client sends everything; Yjs drops what's known → replicas converge
